# Contributing to UPI QR Splitter

Thank you for your interest in contributing to **UPI QR Splitter**!

## Guidelines
1. **Local-First & Offline Principle**:
   - Never add network dependencies, internet permissions, or cloud services.
   - All processing, validation, and QR rendering must remain 100% on-device.
2. **Code Style & Quality**:
   - Follow Kotlin official code style.
   - Ensure all unit tests pass before submitting a Pull Request (`./gradlew testDebugUnitTest`).
3. **Pull Request Process**:
   - Fork the repository.
   - Create a feature branch.
   - Open a PR with a clear summary of changes and test evidence.
